# Honeycomb — card art prompts (round 07 A, Brienne rewritten)

> Write a first pass of art prompts for each card to be sent through the WEBUI engine using the
> character's characterDB entry, the default costume, scene, and background tags.

Generated by `../tools/card-prompts.js`. Each line is a webui v2 shortcut: the character's charactersDB
entry, `default`, then the rest. Identity and outfit are already in those two tokens — do not
restate them. Send a line through `refs-generate.js` the same way a pose slot is sent; the
character's `-basic-a` is the ControlNet reference as always.

**Brienne is hand-authored (session 23, pass 3).** The card window is a stamp (`outputTest.jpg`):
a real scene with a dominant colour cast, a second mass (monster / hands / body), and lust
cards replace `default` with `nude`. No caves, no flat colour fields. Horizontal → `Landscape`;
vertical → `Portrait`. Fighting shots want the reference window at 0.3–0.8; nude shots skip
ControlNet so the clothed `-basic-a` does not put the suit back on.

Anything with a `†` was shaped by a per-card override. Scope: draftable character cards
(starter / common / rare), the neutral pool and the specials. Enemy moves and broken forms are
out of this pass.

## Sending a batch

1. Paste a prompt line into the webui engine (or extend `refs-generate.js`'s slot list) as
   the clean prompt; the engine compiles it exactly as it compiles a pose slot.
2. Reference: the character's `-basic-a` (ControlNet `reference_only`, 0.7–1.0, style 0.5).
3. Size `Portrait` (832×1216) for a vertical card, `Landscape` (1216×832) for a horizontal
   one. Action poses want the ControlNet reference window at 0.3–0.8 so they do not freeze
   on `-basic-a`. The card frame's window rectangles are in `tuning.art.cardFrame`.
4. Keep what passes review in `v13 spire images/cards/art/<cardIndex>.webp`; the game picks it
   up with no code change.
