# Balance tests — INFERENCES

Choices `BRIEF.md` makes that Noodle did not make himself. Each one is a `PARAMS` value or a small rule,
so changing his mind is a one-line edit. Add to this file when a new guess is made; never put guesses in
the brief.

| # | The guess | Where it lives | How to change it |
|---|---|---|---|
| I1 | Basic Bite calls an encounter "far from its target" when a measurement is more than twice the tolerance `tuning.balance` already allows (the existing rule is ±25% of the group target, so "far" starts at ±50%). | `PARAMS.farFactor` in **basic-bite.js** | change the number |
| I2 | The "deckbuilding is ending early" warning fires when the learned bot takes a card at fewer than 25% of the offers in the last third of a run. | `PARAMS.stalePickRate` in **all-the-crunch.js** | change the number, or tell the builder what rate would worry him |
| I3 | Path choice is a plain rule: score every path to the boss by node type, with weights that depend on health and gold (fight elites when healthy, rest when hurt, shop when rich). The starting weights are the builder's. | `PARAMS.pathWeights` in **run-player.js**, printed at the top of every report | edit the weights |
| I4 | In career mode, each run fields the three shipped characters with the least EXP spent, so all six trees fill at about the same pace. A real player probably has favourites, which would fill two or three trees fast and the rest slowly. | `PARAMS.careerPartyRule` | the other rule worth having is "random party each run"; Noodle to say which is closer to a real player |
| I5 | Career mode spends EXP on the cheapest legal node, again and again. A real player aims at specific nodes. | **run-player.js** | a learned rule is possible later, the same way cards are learned |
| I6 | The outcome the bot learns from is "how many more fights did the run win after this decision", plus a bonus for finishing the run. | `PARAMS.runFinishBonus` | change the bonus; a bigger one makes the bot care more about winning the run than about getting far |
| I7 | Learned values are kept per stage of the run and not per deck size, to keep enough samples behind each value. | **run-player.js** | add deck-size buckets if the overnight sample turns out large enough |
| I8 | The second look at setup cards tries at most 3 first moves per turn and 3 follow-ups for each. Session 53 measured 8 and 8 at 2.4 times the old time per fight and 3 and 3 at 1.8 times, for nearly the same play. | `PARAMS.setupFirstMoveCapPerTurn`, `setupFollowUpCap` in **lib/combat-player.js** | raise the two numbers for a more careful bot at a higher time cost |
| I9 | A choice card is tried once per option for its FIRST question only. A second question on the same card is answered with the first option. | `playMove` in **lib/combat-player.js** | extend the probe to later questions if a card is found that asks two |
| I10 | The bot's shop visit buys cards and relics and pays for removals. It ignores the shop's other tabs (treatments, outfits). | `stepShop` in **lib/run-player.js** | add a decision kind for each tab |
| I11 | Learned values are trusted only with at least 12 samples on each side. When any option in a decision has no trusted value, the whole decision is made at random. This keeps the learned bot close to random until the explore batch is large. | `PARAMS.minimumSamples` in **lib/policies.js**, `learnedPolicy` in **lib/learning.js** | lower the number, or change the rule so untrusted options are treated as neutral |
| I12 | A career's "100% of a tree" is the ranks held out of the most a tree can hold, counting one member of each exclusive group. Anastasia's tree is not counted because she cannot join a party before release. | `treeCapacity` in **lib/career.js** | count outfit trees, or add her tree once she ships |
| I13 | The career bot buys the Grandmaster's Invitation whenever a shop offers it, and is otherwise the same bot as everywhere else. A real player would decide to go for it. | `PARAMS.goalRelicArray` in **lib/career.js** | empty the list to see whether the bot ever gets the relic by chance |
| I14 | The run player states one rule of its own, the test the "region cleared" screen uses to choose between descending and finishing (`regionsCleared + 1 < tuning.map.route.regionsPerRun`), because it sits inside that screen's render. | `moreToCome` in **lib/run-player.js** | move it into an engine function the screen also calls, if the rule ever changes |
