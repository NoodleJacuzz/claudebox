# SIMPLE-CHANGELOG

The draft of the next `writeChangelog` entry (`scripts/gameplay/scenewriting.js`), kept as it lands
so nothing is forgotten at release. Rules, from Noodle, 2026-09-26:

- **One line per change, the moment it lands in the game.** Player-facing only: what a player notices
  going from the last release to the next. Dev tools, documents, tests, refactors and anything gated
  behind `inDevelopment` never appear here.
- **A bug players never saw has no line.** If a feature is new in this build and its bug is fixed before
  the build ships, the fix is not a Bugfix; delete the line if one was written. Bugfixes are for bugs
  that were live in the previous release.
- **Written in the voice of `writeChangelog`**: past tense, no code names, a parenthetical only when a
  player needs to know how to reach the thing. Lines are precious; the changelog goes into the release post.
- **The sections are his**: New Content, Removed Content, Other changes, Bugfixes, then one section per
  mod or side game that shipped in the build (Content Restoration Mod, Honeycomb Catacombs).
- **When a build ships**, its lines move into `writeChangelog` and this file starts over with the next
  version's heading. Nothing here describes a build that is already out.
